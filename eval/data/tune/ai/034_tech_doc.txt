# コントリビューションガイド

tsukimi に興味を持っていただき、ありがとうございます！
バグ報告、機能の提案、ドキュメントの改善、コードの修正など、どんな形の貢献も歓迎しています。

## Issue を立てる前に

- 同じ内容の Issue がすでにないか、[Issues](../../issues) で検索してください
- 使い方に関する質問は、Issue ではなく [Discussions](../../discussions) にお願いします

### バグ報告

バグを報告する際は、以下の情報を含めてください。

- tsukimi のバージョン
- OS と Python のバージョン
- 問題を再現する手順（できれば最小限のコード）
- 期待した動作と、実際の動作

### 機能の提案

新しい機能を提案する場合は、まず Issue で「なぜその機能が必要か」を説明してください。実装に取りかかる前にメンテナーと方向性をすり合わせておくと、せっかくのプルリクエストが無駄になることを防げます。

## 開発環境の準備

```bash
git clone https://github.com/example/tsukimi.git
cd tsukimi
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## プルリクエストの流れ

1. リポジトリをフォークし、`main` から作業用のブランチを作成します（例：`fix/parse-empty-line`）
2. 変更を加え、テストを追加・更新します
3. 以下のコマンドで、テストとリンターが通ることを確認します

   ```bash
   pytest
   ruff check .
   ```

4. プルリクエストを作成し、テンプレートに沿って内容を記入します

### プルリクエストのポイント

- 1つのプルリクエストでは、1つの変更に絞ってください
- 関連する Issue がある場合は、本文に `Closes #123` のように記載してください
- ユーザーに見える変更を加えた場合は、`CHANGELOG.md` の「Unreleased」に追記してください

## コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/) の形式を推奨しています。

```
fix: 空行を含むファイルのパースに失敗する問題を修正
```

## 行動規範

このプロジェクトに参加するすべての方は、[行動規範](CODE_OF_CONDUCT.md) を守ってください。お互いを尊重し、誰もが気持ちよく参加できる場にしていきましょう。

わからないことがあれば、気軽に Discussions で質問してください。初めてのコントリビューションも大歓迎です！
