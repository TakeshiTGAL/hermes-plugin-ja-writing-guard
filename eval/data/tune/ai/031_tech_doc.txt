# 障害報告書：一部ユーザーがログインできない事象（2026年9月24日）

## 1. 概要

2026年9月24日 18:05〜19:32 の約1時間27分、Android アプリの一部ユーザーがログインできない状態が発生しました。Web 版および iOS アプリへの影響はありませんでした。

## 2. 影響

- 影響を受けたユーザー：Android アプリ バージョン 5.8.0 以前を利用しているユーザー（ログインを試みたのは約6,300名）
- 事象：ログイン画面で正しいパスワードを入力しても「認証に失敗しました」と表示される
- すでにログイン済みのユーザーは、影響を受けませんでした
- データの消失や、情報の漏えいはありません

## 3. 経緯

| 時刻 | 内容 |
|---|---|
| 17:50 | 認証サーバーのライブラリ更新をリリース |
| 18:05 | ログイン失敗率が上昇し始める |
| 18:22 | カスタマーサポートに問い合わせが集中し、開発チームへエスカレーション |
| 18:40 | 失敗が Android の旧バージョンに集中していることを特定 |
| 19:10 | 17:50 のリリースを切り戻すと判断 |
| 19:32 | 切り戻し完了。ログイン失敗率が通常の水準に戻る |

## 4. 原因

認証ライブラリの更新により、ログイン時のリクエストに含まれる日時の形式のチェックが厳しくなりました。Android アプリの 5.8.0 以前は、タイムゾーンを省略した形式で日時を送っていたため、新しいチェックで不正なリクエストとして扱われました。

ステージング環境での検証は iOS と最新の Android アプリでのみ行っており、旧バージョンのアプリでのテストが漏れていました。

## 5. 対応

### 暫定対応（実施済み）
- 認証サーバーのライブラリを更新前のバージョンに戻しました。

### 恒久対応
1. 認証サーバー側で、タイムゾーンが省略された日時も受け付けるよう修正する（10月2日リリース予定）
2. ステージングでのリリース前テストに、サポート対象のすべてのアプリバージョンを含める
3. ログイン失敗率に対するアラートの閾値を見直し、検知までの時間を短くする

## 6. 再発防止に向けて

今回は、検知から原因の特定までに約35分かかりました。サポート対象のアプリバージョンを一覧で管理し、リリース前のチェックリストに組み込むことで、同様の事象を防ぎます。

ご迷惑をおかけしたユーザーの皆さまに、深くお詫び申し上げます。
