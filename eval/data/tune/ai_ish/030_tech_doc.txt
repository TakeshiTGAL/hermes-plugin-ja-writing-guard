## 障害報告：決済処理のタイムアウト（2026-09-24）

### 概要
9月24日 19:42〜20:31（49分間）、ECサイトの注文確定時に決済処理がタイムアウトし、一部の注文が失敗した。影響を受けた注文は 312 件（同時間帯の注文の約18%）。二重決済は発生していない。

### 原因
19:30 のセール開始に合わせ、注文 API のワーカー数を 8 から 24 に増やした。一方で、決済サービスへの HTTP クライアントのコネクションプールの上限（20）は据え置きだったため、ワーカーが空きコネクションを待ち、タイムアウト（10秒）を超えた。

### 対応
- 20:18 コネクションプールの上限待ちが原因と判明
- 20:25 プール上限を 60 に変更してデプロイ
- 20:31 エラー率が通常値に戻ったことを確認
- 失敗した 312 件の注文者には、9月25日にお詫びのメールとクーポンを送付済み

### 再発防止
- ワーカー数を変更する際は、外部接続のプール上限を同じ PR で見直す（チェックリストに追加済み）
- コネクション待ち時間をメトリクスに追加し、1秒超で通知する

本件を教訓とし、より堅牢なシステムの構築に努めてまいります。
