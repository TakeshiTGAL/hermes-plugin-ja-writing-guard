# 設計メモ：商品詳細ページのキャッシュ戦略

## 目的

商品詳細ページの表示速度を改善し、セール時のアクセス集中でもデータベースへの負荷を抑える。

## 現状の課題

- 商品詳細ページは1回の表示で DB に 8〜12 本のクエリを発行している
- 平常時の p95 は 650ms だが、セール開始直後は 2 秒を超える
- 在庫数や価格は頻繁に変わるため、ページ全体を長時間キャッシュすることはできない

## 方針

ページを「変わりにくい情報」と「変わりやすい情報」に分け、それぞれ異なるキャッシュを適用する。

### 1. 変わりにくい情報（商品名・説明文・画像・スペック）

- Redis に商品単位でキャッシュする
- TTL は 24 時間
- 管理画面で商品情報が更新されたときに、該当キーを削除する（イベント駆動で無効化）

### 2. 変わりやすい情報（価格・在庫数）

- キャッシュはするが、TTL を 30 秒と短くする
- 在庫が残り 5 個以下になった商品は、キャッシュを使わず DB から直接取得する
- カートに入れる時点では、必ず DB の値で再確認する

### 3. CDN

- HTML 全体は CDN でキャッシュしない
- 画像と静的ファイルのみ CDN を利用する

## 検討した代替案

**ページ全体を CDN で短時間キャッシュする案**
実装は最も簡単だが、価格や在庫の表示がずれるリスクがあるため見送った。

**価格・在庫をクライアント側から別 API で取得する案**
キャッシュの扱いはシンプルになるが、初回表示時にちらつきが出るため、今回は採用しない。将来的には再検討の余地がある。

## リスクと対策

- **キャッシュの無効化漏れ**：商品更新のイベント経路を一本化し、更新処理のテストで無効化を確認する
- **キャッシュスタンピード**：TTL 切れの瞬間にアクセスが集中しないよう、TTL にランダムな揺らぎ（±10%）を持たせる

## 次のステップ

1. 変わりにくい情報のキャッシュを先に実装し、効果を計測する
2. 計測結果を見て、価格・在庫の TTL を調整する
