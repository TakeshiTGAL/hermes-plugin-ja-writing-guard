手順書：本番データベースのバックアップからの復元

この手順は、本番DB（PostgreSQL 16）のデータを誤って削除・更新した場合に、特定の時点の状態を別のインスタンスに復元し、必要なデータを取り出すためのものです。本番DBそのものを巻き戻す手順ではありません。

前提
- 作業者は、クラウドコンソールの「db-restore」ロールを持っていること
- 作業前に、チームのチャンネルで作業開始を宣言すること

1. 復元する時点を決める
誤操作が行われた時刻を、アプリのログか監査ログで確認します。その1分前を復元時点とします。時刻はUTCで扱ってください。

2. 復元用インスタンスを作る
コンソールの「データベース」→「prod-main」→「ポイントインタイム復元」を開き、次のとおり指定します。
- 復元時点：手順1で決めた時刻
- インスタンス名：`restore-YYYYMMDD-作業者名`
- ネットワーク：`private-ops`（本番アプリから接続できないネットワーク）

作成には20〜40分かかります。

3. データを取り出す
踏み台サーバーから復元用インスタンスに接続し、必要な行だけをCSVに書き出します。

```
psql -h <復元用ホスト> -U ops -d app \
  -c "\copy (SELECT * FROM orders WHERE id IN (...)) TO 'orders_restore.csv' CSV HEADER"
```

4. 本番に戻す
取り出したデータを本番に戻す作業は、必ず2人で行います。投入用のSQLを1人が書き、もう1人がレビューしてから実行してください。

5. 後片付け
復元用インスタンスは、作業完了後に削除します。残しておくと1日あたり約3,000円かかります。削除したらチャンネルで報告してください。
